# 串口工具功能完善与可配置界面设计草案

状态：用户已确认设计并授权自主实施；每个验证阶段提交 Git 并推送 GitHub，提交与文档标注 AI 辅助。

## 目标与风格

沿用现有 GPUI 界面的白色圆角卡片、轻阴影、紫色焦点边框、绿色 Rx 和蓝色 Tx。面向 Windows 串口调试场景，提供稳定收发、明确错误提示、可配置工作区及数据分析功能。商用就绪需要编译、自动化验证、长时间运行和真实设备验收，不能仅凭界面完成宣称达到。

## 方案选择

1. 推荐：保留现有技术与风格，模块化完善功能，加入显示设置和布局预设。改动范围可控，兼顾已有操作习惯与功能完整性。
2. 仅修补当前功能并增加显示开关：交付较快，但不覆盖 README 的数据解析目标和完整调试流程。
3. 重建为可拖拽停靠工作区：自由度高，但显著增加布局、状态恢复与交互验证成本，当前阶段不采用。

## 界面与布局

- 顶部保留窗口控制，新增始终可用的“视图”入口和恢复默认布局操作。
- 左侧配置区包含串口配置、收发编码和字体设置；右侧工作区包含接收日志、发送日志、发送编辑器和数据波形；底部为连接与收发统计。
- 上述区域均可独立显示或隐藏。隐藏仅影响显示，不停止收发、清除数据或改变计数；隐藏整个配置区后工作区占满可用宽度。
- 提供“标准调试”“数据分析”“精简”预设，用户更改后保存为自定义布局。全部工作区域隐藏时显示空状态和恢复按钮。
- 配置区宽度与工作区采用合理最小尺寸，窄窗口使用滚动和纵向排列；控件不溢出，日志区扩展利用剩余空间。
- 显示选择、字体、串口参数、编码与定时发送间隔持久化。启动恢复偏好，但不自动打开串口或启动定时发送。

## 功能范围

### 串口与可靠收发

支持无流控、RTS/CTS 和 XON/XOFF；连接前设置参数，连接后限制不适用的配置操作。打开成功且句柄就绪后才发布连接成功状态。

将阻塞串口读写置于后台执行，关闭过程不忙等阻塞界面。每次连接拥有独立的会话和取消状态，旧会话不得污染新连接。读队列采用容量限制，并明确处理拥塞。

正确处理部分写入、零字节写入、超时、设备拔出及写失败；发送偏移和计数按实际成功字节更新，失败可见且可恢复。保留已有流式文本解码和日志行数限制，验证跨包字符和 CR/LF 边界。

### 调试操作

保留文本与十六进制收发、时间戳、自动滚动、复制和清空。十六进制输入必须严格校验，异常输入不能静默变更为另一组字节。

补齐定时发送及停止操作，校验间隔、避免并发重叠，断开连接自动停止。提供发送日志和接收日志导出，以及单独重置统计操作。文件操作显示成功或失败，覆盖已存在文件时明确确认。

### 数据解析与波形

首期覆盖 VOFA 常用 JustFloat 帧和以换行分隔的逗号数值文本。解析器独立于 UI，支持分包、粘包、异常输入、缓冲上限和连接重置。

波形面板提供协议选择、通道显隐、通道颜色/图例、暂停显示、清空和 CSV 导出。原始串口接收不因波形暂停而停止。采样缓存与绘制刷新率有上限，防止持续接收造成内存无限增长。

## 实现边界

通信生命周期由串口会话管理；编码与协议解析由独立模型负责；用户偏好由版本化配置负责；各界面面板只负责交互和显示。只调整与本次目标相关的结构，不重写无关代码。

配置不存在时使用默认值；配置损坏时提示并回退，避免启动崩溃；保存失败时保留当前会话设置并显示提示。用户已有的 crates/ww-ui/src/ui/info.rs 修改需要保留。

## 验收

- 编译检查与适用的格式检查通过。
- 自动化覆盖部分写入、发送计数、无效 Hex、分包协议、缓存上限和偏好恢复。
- 检查各种区域显隐组合、全部隐藏后的恢复、窄窗口布局和连接状态反馈。
- 真机验收包括流控、持续高频收发、设备拔出、重复连接、定时发送取消和关闭窗口。
- 无真实设备或图形运行环境时明确列出未验证项；最终记录已完成范围与剩余商用验收项。
